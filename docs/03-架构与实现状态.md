# 架构与实现状态

本文说明当前代码的职责和行为。准确版本以 `package.json` 为准，发布记录见
[更新日志](../CHANGELOG.md)。现有外观覆盖范围及限制见本文“外观边界”。

## 从源数据到界面

| 层 | 文件 | 职责 | 修改后的操作 |
| --- | --- | --- | --- |
| 调色板 | `src/palette.py` | libadwaita 变量、强调色、透明度合成 | 构建主题 |
| 界面映射 | `src/mapping.py` | 将颜色角色映射为 VS Code 颜色键 | 构建主题 |
| 语法映射 | `src/tokens.py`、随附 XML | GtkSourceView 到 TextMate 与语义高亮 | 构建主题 |
| 生成器 | `src/build.py` | 生成 JSON、同步主题清单、校验颜色与键表 | 检查产物差异 |
| 主题产物 | `themes/` | VS Code 读取的颜色与语法主题 | 必须随源修改提交，不手工编辑 |
| 外观补丁 | `extras/*.css`、`extras/window-state.js` | 工作台几何、阴影、焦点、窗口按钮及非活动状态同步 | 同步安装副本并手动加载 |
| 扩展 | `extension/extension.js` | 命令、强调色跟随、CSS 安装、状态面板与自动重载 | 类型检查与离线测试 |
| 打包 | `src/package.py` | 无 Node.js 构建依赖的 VSIX 归档 | 检查版本、清单与归档内容 |
| 发布说明 | `src/release_notes.py` | 从当前版本更新日志提取公开说明 | 缺少或空白版本章节时失败 |

扩展不依赖构建过程或第三方运行时库。新增 VS Code 或 Node.js API 时，在
`types/` 中补充最小声明，并通过类型检查；不要引入 `@types` 依赖。

## 外观安装链路

“安装 GNOME 外观”复制 `gnome-look.css` 与 `controls-close-only.css`，并生成读取
GNOME 界面字体的 `gnome-fonts.css`，连同 `window-state.js` 安装到
`~/.config/adwcode/`。本次组件的源码及副本引用统一为单份副本 URI，合并到
`vscode_custom_css.imports`；其他目录的用户加载项及其顺序保留。
安装命令基于用户级值合并，工作区值不会被复制回用户设置。
若工作区覆盖仍缺少组件或包含重复引用，会保留覆盖并提示手动处理，暂不提供补丁按钮。
未安装加载器时，剪贴板中的设置片段可直接粘贴为 JSONC 配置。
加载器把文件内容内联进工作台 HTML；窗口重新加载后才读取新的 HTML。

因此需要分别识别以下状态：

1. 仓库文件已经修改。
2. 安装副本与仓库文件一致。
3. 加载器配置引用了文件。
4. 磁盘上的工作台 HTML 已注入当前内容。
5. 当前窗口已经加载该内容。

状态面板检查前四类证据，不能直接确认第五类。它也识别直接引用仓库源文件的
文件 URI，并提示重复配置与重复注入；变量占位符、其他克隆目录等特殊 URI
尚未做完整识别。磁盘内容检测限定在
加载器的注入标记之间，不能把 HTML 其他位置的文本当成生效证据。

“生成仅关闭按钮的窗口控件 CSS”只安装窗口按钮补丁。其他用户加载项应保留。
安装过程会清理遗留的 `gnome-menu.js` 副本引用；该脚本已移除。

非活动状态脚本只观察原生标题栏的 `class`，将状态同步到标签、工具栏标题和
活动栏容器。工作台尚未创建时只在启动阶段等待 DOM；非活动期间另观察布局结构，
补充新增导航容器的状态，忽略文本行和列表内容变化，恢复活动后停止布局观察。
不轮询、不改正文、不移动菜单；重复注入会释放旧观察器，页面关闭时清理状态。
没有加载脚本时，几何样式仍可用，跨区域的非活动弱化不生效。

## 已实现的扩展行为

- `adwcode.autoAccent` 默认开启，跟随 GNOME 强调色，同步 AdwCode 当前主题及
  普通明暗首选主题的已安装变体；其他主题及高对比度值保持原样。
  异步读取完成后再次核对会话、开关及主题值；忽略过期结果，不覆盖读取期间的手动切换。
  工作区覆盖的主题值保持原样，也不会将其导出到用户级首选配置；手动同步时提示处理覆盖。
- `adwcode.autoReload` 默认与推荐均关闭，手动开启后监视外观、主题、清单
  与扩展文件，约 1.5 秒防抖后同步已安装的 CSS 副本、重新应用加载器并重载。
  加载器更新失败时取消重载；配置关闭和扩展停用会清理待执行任务与监视器。
  系统读取与副本写入完成后再次检查是否允许继续，关闭后不再调用加载器。
  重新开启不会恢复此前已取消的异步操作。
- “查看外观安装状态”是只读面板，支持手动刷新，不安装文件、不修改配置、
  不执行窗口重载。
- 推荐设置先预览，再写入系统明暗与高对比度主题、产品图标、GNOME 代码字体、
  窗口控件及布局的用户级值；项目开发配置由工作区管理。跳过当前 VS Code
  未注册的配置，先写入自动重载关闭值，工作区覆盖开启时明确提示。
  命令结束只提示手动重载，不执行重载命令。
- 推荐设置记录覆盖前的全局值，恢复命令按记录恢复，包括原有自动重载状态；
  用户随后改值的保护仍属于后续工作。重复应用保留首次原值，写配置前逐项记录，部分失败
  时保留剩余恢复记录。恢复仍会覆盖用户随后手动更改的值，不宣称完整安全快照。
- 扩展命令当前只在 Linux 上注册；不能仅根据主题可安装就宣称所有平台行为一致。

## 外观边界

颜色主题负责颜色，CSS 负责几何。修改 CSS 时保留 VS Code 计算的列表行高、
滚动位置、活动栏图标盒子和控件定位。不要在菜单祖先上随意添加 `transform`，
它会改变固定定位的参照，可能造成遮挡或裁切。

普通滚动条采用横截面内缩与较低透明度；高对比度保留完整滑块和更清晰配色。
键盘焦点独立于选中状态，容易裁切的操作区使用内侧描边。

UI-01 至 UI-10 已实现背景分层、控件状态、按用途拆分列表、浮层、设置分组、
非活动状态、界面字体、常用产品图标和状态面板。实现与界面验证的具体范围见
[外观实现与验收](05-外观实现与验收.md)，不能将单个版本验证等同于全平台 HIG 认证。
