# 架构与实现状态

本文说明当前代码的职责和行为。准确版本以 `package.json` 为准，发布记录见
[更新日志](../CHANGELOG.md)。现有外观覆盖范围及限制见本文“外观边界”。

## 从源数据到界面

| 层 | 文件 | 职责 | 修改后的操作 |
| --- | --- | --- | --- |
| 调色板 | `src/palette.py` | libadwaita 变量、强调色、透明度合成 | 构建主题 |
| 界面映射 | `src/mapping.py` | 将颜色角色映射为 VS Code 颜色键 | 构建主题 |
| 语法映射 | `src/tokens.py`、随附 XML | GtkSourceView 到 TextMate 与语义高亮 | 构建主题 |
| 生成器 | `src/build.py` | 生成 JSON、同步主题清单、校验颜色与键表 | 检查产物差异 |
| 主题产物 | `themes/` | VS Code 读取的颜色与语法主题 | 必须随源修改提交，不手工编辑 |
| 外观补丁 | `extras/*.css` | 工作台几何、阴影、焦点和窗口按钮 | 同步安装副本并手动加载 |
| 扩展 | `extension/extension.js` | 命令、强调色跟随、CSS 安装、状态面板与自动重载 | 类型检查与离线测试 |
| 打包 | `src/package.py` | 无 Node.js 构建依赖的 VSIX 归档 | 检查版本、清单与归档内容 |

扩展不依赖构建过程或第三方运行时库。新增 VS Code 或 Node.js API 时，在
`types/` 中补充最小声明，并通过类型检查；不要引入 `@types` 依赖。

## 外观安装链路

“安装 GNOME 外观”复制 `gnome-look.css` 与 `controls-close-only.css`，并生成读取
GNOME 界面字体的 `gnome-fonts.css` 到
`~/.config/adwcode/`，将副本 URI 合并到 `vscode_custom_css.imports`。
加载器把文件内容内联进工作台 HTML；窗口重新加载后才读取新的 HTML。

因此需要分别识别以下状态：

1. 仓库文件已经修改。
2. 安装副本与仓库文件一致。
3. 加载器配置引用了文件。
4. 磁盘上的工作台 HTML 已注入当前内容。
5. 当前窗口已经加载该内容。

状态面板检查前四类证据，不能直接确认第五类。它也识别直接引用仓库源文件的
文件 URI；变量占位符等特殊 URI 配置尚未做完整解析。磁盘内容检测限定在
加载器的注入标记之间，不能把 HTML 其他位置的文本当成生效证据。

“生成仅关闭按钮的窗口控件 CSS”只安装窗口按钮补丁。其他用户加载项应保留。
安装过程会清理遗留的 `gnome-menu.js` 副本引用；该脚本已移除。

## 已实现的扩展行为

- `adwcode.autoAccent` 默认开启，跟随 GNOME 强调色，仅在当前使用 Adwaita
  主题时切换已安装的对应变体；不是任意主题的颜色重写功能。
- `adwcode.autoReload` 默认关闭，推荐设置会将它开启。监视外观、主题、清单
  与扩展文件，约 1.5 秒防抖后同步已安装的 CSS 副本、重新应用加载器并重载。
  加载器更新失败时取消重载；配置关闭和扩展停用会清理待执行任务与监视器。
- “查看外观安装状态”是只读面板，支持手动刷新，不安装文件、不修改配置、
  不执行窗口重载。
- 推荐设置记录覆盖前的全局值，恢复命令按记录恢复；重复应用、用户随后改值
  的保护机制仍属于后续工作，不宣称已具备安全快照功能。
- 扩展命令当前只在 Linux 上注册；不能仅根据主题可安装就宣称所有平台行为一致。

## 外观边界

颜色主题负责颜色，CSS 负责几何。修改 CSS 时保留 VS Code 计算的列表行高、
滚动位置、活动栏图标盒子和控件定位。不要在菜单祖先上随意添加 `transform`，
它会改变固定定位的参照，可能造成遮挡或裁切。

普通滚动条采用横截面内缩与较低透明度；高对比度保留完整滑块和更清晰配色。
键盘焦点独立于选中状态，容易裁切的操作区使用内侧描边。

当前已有圆角、阴影、通知、工具栏、输入框、设置行等首轮适配。背景层级、
全局列表规则的分类、完整按钮状态和设置页分组尚待完善。不能把首轮适配
等同于完成 GNOME HIG 验证。
