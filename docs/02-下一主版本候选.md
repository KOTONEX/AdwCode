## 当前外观待实现清单

以 GNOME HIG、libadwaita 1.10 和 GNOME Builder 为依据，按以下顺序推进。
实施状态见 [外观实现与验收](05-外观实现与验收.md)；实现和实际界面验收分别记录。

| 编号 | 工作 | 完成标准 |
| --- | --- | --- |
| UI-01 | 背景层级与分隔线 | 明确顶栏、侧栏、内容和面板层级，减少重复边框 |
| UI-02 | 完整按钮状态 | 核对默认、悬停、按下、选中、禁用和键盘焦点 |
| UI-03 | 按用途拆分列表样式 | 树、搜索、补全保持紧凑，设置列表独立处理，替换全局内缩 |
| UI-04 | 控件尺寸与间距 | 工具栏、输入框和标签视觉对齐，不破坏布局计算 |
| UI-05 | 浮层层级 | 菜单、提示、通知和对话框分别适配，检查展开和裁切 |
| UI-06 | 设置页分组 | 标题、说明、背景和分隔形成清楚层级，保留搜索与键盘操作 |
| UI-07 | 非活动窗口状态 | 工具栏与标签自然弱化，正文仍可读 |
| UI-08 | 界面字体 | 核对实际 GNOME 字体，与代码字体分开配置并验证回退 |
| UI-09 | 高频产品图标 | 覆盖常用侧栏和工具栏，保持含义与字重一致 |
| UI-10 | 扩展界面与文案 | 状态面板分组和提示符合 HIG，已实现与未知状态区分清楚 |
| UI-11 | 无障碍与兼容验证 | 每轮检查键盘、浅深色、高对比度、缩放及遮挡 |

先推进 UI-01 至 UI-05，再推进 UI-06 至 UI-10；UI-11 贯穿每轮。
汉堡菜单保持原生位置，不再列为位置修改任务。独立截图回归仍是候选能力。

## 其他版本候选

| 候选改动 | 用户收益 | 成本 / 风险 | 建议优先级 |
| --- | --- | --- | --- |
| 将推荐设置分成外观、布局、开发三组，自动重载仅在开发组开启 | 日常工作和扩展会话不会因改动文件意外中断 | 中；改变现有推荐设置行为，需要迁移说明 | 高 |
| 外观模块独立开关：圆角、滚动条、窗口按钮 | 能按个人偏好组合，也便于定位兼容问题 | 中；安装与卸载必须只修改本扩展管理的加载项 | 高 |
| 安全更新模式：文件变化只提示；由用户点击命令应用并重载 | 兼顾开发反馈与持续工作的会话 | 中；CSS 原位更新可另行研究，扩展代码更新仍需重载 | 高 |
| 设置快照与逐项恢复，不覆盖用户在应用后手动更改的值 | 推荐配置更容易撤销，避免丢失后续调整 | 中；重复应用与部分失败需要明确恢复语义 | 高 |
| 舒适 / 紧凑两种几何预设 | 大屏、触控与高密度编码场景各有合适的间距 | 高；列表行和标签高度受 VS Code 布局计算约束 | 中 |
| 建立浅色、深色、高对比度的界面截图回归集 | 升级前发现菜单遮挡、裁切、缩放和焦点问题 | 高；需要独立测试窗口，不能重载用户工作窗口 | 高 |
| 扩大外观覆盖：通知、命令面板、搜索、设置页、终端标签 | 常用界面的圆角、间距和状态更加一致 | 中至高；按组件推进并验证键盘导航 | 中 |
| 明暗模式与强调色组合预览 | 更容易选主题，不必逐个切换试验 | 中；系统跟随应可单独关闭 | 中 |
| CSS 兼容性报告支持选择器结构与 JS 创建的类名 | 降低“类名存在但规则没命中”的误判 | 中至高；单纯字符串扫描不足，需要 DOM 验证 | 中 |

## 建议的 2.0 范围

分组推荐设置、模块开关、安全更新和设置恢复继续保留为候选，尚未确认实施。
这些方向围绕当前已经遇到的实际问题，截图回归作为发布前验证基础。
几何预设与更广的组件覆盖可在上述基础稳定后逐步加入。

## 已有基础与验证要求

- 滚动条仅在横截面内缩，不再缩短可见滑块；高对比度恢复完整滑块面积。
- 汉堡菜单保留 VS Code 原生位置，已移除菜单位置脚本；自动重载可能中断扩展会话。
- 静态检查不能代替界面验证。手动加载外观后，应检查菜单及子菜单、
  键盘焦点、横纵滚动条、浅深主题和高对比度；整个过程不自动重载用户窗口。
