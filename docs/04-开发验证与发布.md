# 开发、验证与发布

## 开始工作

先阅读 [AGENTS.md](../AGENTS.md)，查看 `git status --short` 与本次任务涉及的
差异。已有修改和未跟踪文件可能是用户工作；不清空工作区，不执行广泛清理。
任务涉及发布时读取 `package.json`、`CHANGELOG.md` 和发布工作流。

检查用户的自动重载设置，避免修改文件导致当前 Codex 会话中断。不要通过加载器
或窗口重载命令测试真实工作窗口。离线测试使用模拟对象，不操作真实 VS Code。

## 按改动类型验证

| 改动 | 必做验证 | 额外核对 |
| --- | --- | --- |
| 配色、语法映射 | `make build`，完整检查 | 源修改与生成 JSON 一起提交；颜色键合法、对比度合理 |
| CSS 外观 | 完整检查，`python3 src/check_css.py` | 类名检查只是初筛；视觉、裁切和焦点需单独验证 |
| 扩展行为 | 完整检查 | API 类型声明、配置默认值、命令清单和错误路径同步 |
| 文档与提示 | 完整检查 | 简体中文、路径和命令准确，不引用未提交的文件 |
| 发布与打包 | 构建、完整检查、`make package` | 版本一致，产物齐全，不包含待办或调试日志 |

完整检查为：

```sh
make lint && make check && make test
```

`make lint` 包含类型检查，但本地缺少 mypy 或 tsc 时可能跳过；发布前应确认
实际执行，或使用 `ADWCODE_TYPECHECK_STRICT=1 make typecheck`。
离线扩展测试需要 Node.js，缺失时会跳过，不能把跳过报告为验证通过。

`make check` 校验当前产物，不负责证明它们与生成器一致。生成后核对 Git 差异；
CI 的生成校验要求重新构建后 `themes/` 和 `package.json` 不产生额外差异。
不要用 `--accents all` 的产物替换默认构建而忽略发布工作流的构建方式。

## 用户手动预览

1. 配色源码有变化时先 `make build`。
2. 如果用 VSIX 安装扩展，先打包并由用户安装；符号链接开发安装直接读取仓库。
3. 用户执行“Adwaita: 安装 GNOME 外观（CSS）”，更新副本与加载配置。
4. 用户在合适时机执行加载器的“Reload Custom CSS and JS”并重载窗口。
5. 检查浅色、深色、高对比度、键盘焦点、菜单及子菜单、横纵滚动条、缩放与窄窗。

首次尚未启用加载器时，应使用其“Enable Custom CSS and JS”。VS Code 升级后
需要重新应用补丁。命令沿用加载器实际显示名称，不把外部命令自行改名。

记录验证边界：静态检查通过、用户确认某个界面正常、完整截图回归通过，三者
含义不同。避免用旧截图或单个界面作为全部外观已验证的依据。

## 提交与发布

1. 明确本次提交范围，用具体路径暂存，不用 `git add .` 混入候选文档、日志或
   无关工作。检查暂存差异及 `git diff --cached --check`。
2. 使用 [贡献规范](../CONTRIBUTING.md) 的中文类型前缀，描述最终实际行为。
   正文可列修改原因与验证结果，避免只有“准备发布”等过程性描述。
3. 本机 Git 身份缺失时核对 gh 账号和已有作者信息；必要时询问，不伪造邮箱。
   临时身份可通过 `git -c user.name=… -c user.email=… commit` 指定。
4. 版本只修改 `package.json`，在更新日志中整理对应版本内容。更新版本不等于
   已公开发布，提交也不等于已推送。
5. 打包检查 VSIX 的版本、主题清单和归档完整性；`[Content_Types].xml` 中的
   扩展名不带前导点，CSS 类型为 `text/css`。VSIX 不提交到仓库。
6. 仅在用户授权发布后推送对应 `v<版本>` 标签，触发发布工作流。市场发布需要
   `VSCE_PAT`、`OVSX_PAT`，缺失时工作流跳过对应市场，不宣称市场已经发布。

不要在文档中固定某次提交哈希、工作区是否干净或用户当前设置；这些状态应
在每次执行时检查。待办文档可以保留未提交，若 README 链接到它，提交 README
时必须同时纳入该文档或移除链接。

## 更新项目说明

功能行为变化时同步相关文档：架构说明记录已实现行为，待办记录剩余范围，
更新日志记录版本变化，AGENTS.md 只保留稳定约束和入口。不要复制多份完整
实现说明，也不要把“计划做”写成“已经完成”。
