## 设计与限制

参考 [GNOME HIG](https://developer.gnome.org/hig/)、
[顶栏](https://developer.gnome.org/hig/patterns/containers/header-bars.html)、
[分组列表](https://developer.gnome.org/hig/patterns/containers/boxed-lists.html) 与
[libadwaita 样式](https://gnome.pages.gitlab.gnome.org/libadwaita/doc/1.10/style-classes.html)。
工具栏保持轻量，分组使用标题与间距。VS Code 的虚拟列表仍由其布局引擎管理；
不修改绝对定位行高、滚动位置或菜单定位，不移动汉堡按钮。

## 验证记录

每阶段运行完整 Meson 检查及已安装 VS Code 的 CSS 兼容检查。
界面检查使用独立配置和扩展目录，不修改或重载工作窗口。
浅深色、高对比度、窄窗、缩放、键盘操作与遮挡贯穿验收。

## 第一轮审查：本次提交

逐个审查 UI-01 至 UI-10 的提交，核对颜色生成、CSS 的作用范围、字体生成、
产品图标资产与状态面板。发现 Linux 原有字体规则优先级更高，已提高字体规则的
优先级；状态刷新改为重新读取系统字体并在面板关闭时丢弃结果。
字体转义覆盖引号、反斜线、控制字符与 HTML 分隔符。

自有图标字体再生成结果无差异，字体通过独立浏览器的数据 URI 加载，
字形源与生成文件一致。常规主题不会增加全局对比边框；高对比度保留轮廓。

## 第二轮审查：完整项目

审查范围包括生成器、调色板、颜色与语法映射、随附数据的解析、扩展全部命令、
CSS、产品图标生成、类型面、测试、Meson、CI、打包与项目文档。
本轮修复和验证包括：

- 拒绝非法十六进制颜色、越界 RGB 和透明度；JSONC 尾逗号处理不再误改字符串。
- 检测主题 include 循环；生成成功后才替换旧产物，失败时保留已有主题。
- VSIX 元数据进行 XML 转义，许可证路径与文档打包保持一致。
- 推荐设置重复应用保留首次备份，部分失败和恢复失败保留可重试记录。
- 自动重载关闭或扩展停用后，待执行任务不再继续重载；安装状态检测限定加载器
  补丁区间，不把磁盘证据当成当前窗口证据。
- 菜单阴影移至外壳，禁用工具栏悬停不增加背景；非活动窗口选择器匹配原生结构。
- 文件读写统一明确 UTF-8，去除失效常量，补充解析、打包与配置恢复回归测试。

“恢复推荐设置”仍会恢复备份中的原值，尚不保护应用推荐设置后的手动修改；
这项功能属于其他候选，不作为 UI-01 至 UI-10 的完成条件。

## 本地试用

当前 2.0.0 是本地试用版本，未推送或创建发布标签。开发检查不需要重新应用
推荐设置；该命令会开启自动重载。使用 Codex 扩展时，保持
`"adwcode.autoReload": false`，将窗口重载安排在会话结束之后。

1. 保存工作，安装项目目录中的 `AdwCode-2.0.0.vsix`：

   ```sh
   code --install-extension AdwCode-2.0.0.vsix --force
   ```

2. 选择 Adwaita 颜色主题与 Adwaita 产品图标主题。
3. 确认已安装 Custom CSS and JS Loader，执行
   “Adwaita: 安装 GNOME 外观（CSS）”，更新三个外观组件和加载配置。
4. 结束当前扩展会话后，首次执行加载器的“Enable Custom CSS and JS”；
   已启用时执行“Reload Custom CSS and JS”，按提示手动重载窗口。
5. 检查菜单、设置、搜索、补全、通知、多标签、窄窗、缩放及字体；汉堡菜单
   保留原生位置。可执行“Adwaita: 查看外观安装状态”辅助检查安装文件，
   该命令不会重载窗口。

尚待试用确认的重点是实际加载器链路、日常插件组合和长时间操作体验。
