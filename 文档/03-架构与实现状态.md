# 架构与实现状态

本文说明当前代码的职责和行为。准确版本以 `package.json` 为准，发布记录见
[GitHub 发布页](https://github.com/KOTONEX/AdwCode/releases)。本地变更日志由 Git
历史自动生成，运行方式见 [开发、验证与发布](04-开发验证与发布.md#自动变更日志)。
现有外观覆盖范围及限制见本文“外观边界”。

## 从源数据到界面

| --- | --- | --- | --- |

| 界面映射 | `源码/库/界面映射.rs` | 将颜色角色映射为 VS Code 颜色键 | 构建主题 |
| 语法映射 | `源码/库/语法映射.rs`、随附 XML | GtkSourceView 到 TextMate 与语义高亮 | 构建主题 |
| 主题生成 | `源码/库/主题生成.rs` | 生成 JSON、同步主题清单、校验颜色与键表 | 检查产物差异 |
| 主题产物 | `主题/` | VS Code 读取的颜色与语法主题 | 必须随源修改提交，不手工编辑 |
| 外观补丁 | `附加外观/*.css`、`附加外观/窗口状态.js` | 工作台几何、阴影、焦点、窗口按钮及非活动状态同步 | 同步安装副本并手动加载 |
| 扩展 | `扩展/扩展.js` | 命令、CSS 安装与状态输出 | 类型检查与离线测试 |
| 打包 | `源码/库/打包.rs` | 无 Node.js 构建依赖的 VSIX 归档，自动包含 Git 变更日志 | 检查版本、清单与归档内容 |
| 检查样式 | `源码/库/检查样式.rs` | 对照已安装的 VS Code 核对类选择器与设计令牌 | VS Code 升级后运行 |
| 更新默认数据 | `源码/库/更新默认数据.rs` | 刷新随附的 VS Code 默认数据与颜色键表 | 核对数据与键表差异 |
| 变更日志与发布说明 | `源码/库/变更日志.rs` | 主线版本标签划分范围，提交标题按中文类型分组 | 完整检出历史与标签；发布标签必须对应 HEAD 和清单版本 |
| 发布上传 | `源码/库/发布上传.rs` | 本地与 CI 共用 Release 附件/市场编排，校验标签、源码和 VSIX | Cargo 离线命令模拟与真实标签预演；网络错误失败，附件不一致拒绝复用 |
| 发布策略 | `源码/库/发布策略.rs` | 读取版本、判断主线归属与候选/市场权限、写入 CI 输出 | Cargo 真实临时 Git 仓库回归；缺少主线或历史时失败 |
| 清单设置验证 | `源码/库/验证设置.rs` | 验证默认主题、字体、命令和工作区能力 | 纳入完整检查；错误值与缺失字段回归 |
| 命令行与程序入口 | `源码/库/命令.rs`、`源码/程序/主程序.rs` | 解析子命令并分发；`adwcode` 二进制入口 | 运行 `adwcode <子命令>` |

Rust 侧的检查手段为 `cargo fmt`、`cargo clippy` 与 `cargo test`，产物校验使用
`adwcode 校验`；完整检查由 `cargo run --quiet -- 检查` 聚合，发布产物为
`./target/release/adwcode <子命令>`。

扩展不依赖构建过程或第三方运行时库。新增 VS Code 或 Node.js API 时，在
`类型声明/` 中补充最小声明，并通过类型检查；不要引入 `@types` 依赖。

## 外观安装链路

“安装 GNOME 外观”复制 `GNOME外观.css` 与 `仅关闭窗口控件.css`，并生成读取
GNOME 界面字体的 `GNOME字体.css`，连同 `窗口状态.js` 安装到
`~/.config/adwcode/`。本次组件的源码及副本引用统一为单份副本 URI，合并到
`vscode_custom_css.imports`；其他目录的用户加载项及其顺序保留。
安装命令基于用户级值合并，工作区值不会被复制回用户设置。
若工作区覆盖仍缺少组件或包含重复引用，会保留覆盖并提示手动处理，暂不提供补丁按钮。
未安装加载器时，剪贴板中的设置片段可直接粘贴为 JSONC 配置。
加载器把文件内容内联进工作台 HTML；窗口重新加载后才读取新的 HTML。

因此需要分别识别以下状态：

1. 仓库文件已经修改。
2. 安装副本与仓库文件一致。
3. 加载器配置引用了文件。
4. 磁盘上的工作台 HTML 已注入当前内容。
5. 当前窗口已经加载该内容。

状态输出检查前四类证据，不能直接确认第五类。它也识别直接引用仓库源文件的
文件 URI，并提示重复配置与重复注入；变量占位符、其他克隆目录等特殊 URI
尚未做完整识别。磁盘内容检测限定在
加载器的注入标记之间，不能把 HTML 其他位置的文本当成生效证据。

“安装仅关闭按钮的窗口控件 CSS”只将随包提供的静态窗口按钮补丁原样复制到安装目录。
其他用户加载项应保留。
安装外观时自动移除本扩展源码目录及 `~/.config/adwcode` 中的旧版加载引用；
其他目录中的加载项保持不变，旧文件名不作为功能兼容入口。

非活动状态脚本只观察原生标题栏的 `class`，将状态同步到标签、工具栏标题和
活动栏容器。工作台尚未创建时只在启动阶段等待 DOM；非活动期间另观察布局结构，
补充新增导航容器的状态，忽略文本行和列表内容变化，恢复活动后停止布局观察。
不轮询、不改正文、不移动菜单；重复注入会释放旧观察器，页面关闭时清理状态。
没有加载脚本时，几何样式仍可用，跨区域的非活动弱化不生效。

## 已实现的扩展行为

- “查看外观安装状态”输出到只读通道，再次执行命令即刷新，不安装文件、
  不修改配置、不执行窗口重载。
- 默认设置由 `package.json` 的 `configurationDefaults` 声明：系统明暗与高对比度
  主题、产品图标、GNOME 代码字体、窗口控件及布局值只在用户或工作区未显式设置时
  生效。扩展不改写用户设置，也不提供应用或恢复命令。
- 运行时不判断平台：命令的 `enablement` 与命令面板入口由清单限定为 `isLinux`，
  扩展声明只在 UI 侧运行，并在虚拟工作区和受限模式下不可用。
- 命令当前只在 Linux 提供；不能仅根据主题可安装就宣称所有平台行为一致。

## 外观边界

颜色主题负责颜色，CSS 负责几何。修改 CSS 时保留 VS Code 计算的列表行高、
滚动位置、活动栏图标盒子和控件定位。不要在菜单祖先上随意添加 `transform`，
它会改变固定定位的参照，可能造成遮挡或裁切。

普通滚动条采用横截面内缩与较低透明度；高对比度保留完整滑块和更清晰配色。
键盘焦点独立于选中状态，容易裁切的操作区使用内侧描边。

UI-01 至 UI-10 已实现背景分层、控件状态、按用途拆分列表、浮层、设置分组、
非活动状态、界面字体、常用产品图标和状态输出。实现与界面验证的具体范围见
[外观实现与验收](05-外观实现与验收.md)，不能将单个版本验证等同于全平台 HIG 认证。

## 设计依据

- [GNOME 人机交互指南](https://developer.gnome.org/hig/)
- [顶栏](https://developer.gnome.org/hig/patterns/containers/header-bars.html)
- [侧栏](https://developer.gnome.org/hig/patterns/nav/sidebars.html)
- [分组列表](https://developer.gnome.org/hig/patterns/containers/boxed-lists.html)
- [libadwaita 1.10 样式说明](https://gnome.pages.gitlab.gnome.org/libadwaita/doc/1.10/style-classes.html)

遵循可核对的角色和组件状态；涉及精确取值时查对应版本，不把个人审美判断
写成上游规范。GNOME Builder 用于参照开发工具的信息密度和工作区布局。

性能基准由 Node 执行真实扩展并输出原始样本，Rust 校验样本协议并统一计算摘要。
页面 DOM 与 Playwright 测量仍由 JavaScript 执行。

## 扩展模块边界

`扩展/扩展.js` 装配依赖，`命令.js` 注册命令；`组件.js`、`字体.js`、`引用.js`、
`状态.js`、`事务.js` 由 `外观服务.js` 组合。状态和事务共享同一服务实例，队列串行
协调文件及配置恢复。模块工厂可以注入宿主依赖，扩展仍不需要构建步骤。
