## 其他版本候选

| 候选改动 | 用户收益 | 成本 / 风险 | 建议优先级 |
| --- | --- | --- | --- |
| 外观模块独立开关：圆角、滚动条、窗口按钮 | 能按个人偏好组合，也便于定位兼容问题 | 中；安装与卸载必须只修改本扩展管理的加载项 | 高 |
| 安全更新模式：文件变化只提示；由用户点击命令应用并重载 | 兼顾开发反馈与持续工作的会话 | 中；CSS 原位更新可另行研究，扩展代码更新仍需重载 | 高 |
| 舒适 / 紧凑两种几何预设 | 大屏、触控与高密度编码场景各有合适的间距 | 高；列表行和标签高度受 VS Code 布局计算约束 | 中 |
| 建立浅色、深色、高对比度的界面截图回归集 | 升级前发现菜单遮挡、裁切、缩放和焦点问题 | 高；需要独立测试窗口，不能重载用户工作窗口 | 高 |
| 扩大外观覆盖：通知、命令面板、搜索、设置页、终端标签 | 常用界面的圆角、间距和状态更加一致 | 中至高；按组件推进并验证键盘导航 | 中 |
| 明暗模式与强调色组合预览 | 更容易选主题，不必逐个切换试验 | 中；系统跟随应可单独关闭 | 中 |
| CSS 兼容性报告支持选择器结构与 JS 创建的类名 | 降低“类名存在但规则没命中”的误判 | 中至高；单纯字符串扫描不足，需要 DOM 验证 | 中 |
