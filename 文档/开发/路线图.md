# 路线图

本文只记录尚未实施的候选方向，不承诺版本、发布时间或自动执行。当前功能见
[架构](架构.md) 和 [外观与设置](../使用/外观与设置.md)，历史完成项见 [文档目录](../README.md#历史)。

## 已有基础

已支持整份外观、字体、窗口按钮与状态脚本的多选，以及移除自有加载引用；
事务保留其他加载项并恢复失败操作。独立宿主与工作台验证已可运行，截图回归集尚未建立。

## 候选能力

| 方向 | 收益 | 成本与边界 |
| --- | --- | --- |
| 细粒度外观开关：圆角、滚动条等 | 按偏好组合，定位兼容问题 | 须先拆分 CSS；不与已有整份组件选择重复 |
| 安全更新提示 | 文件变化后由操作者选择何时应用 | 不自动重载；扩展代码与 CSS 更新分别处理 |
| 浅色、深色、高对比度截图回归 | 发现裁切、遮挡、缩放与焦点变化 | 专用窗口与稳定环境；不能中断工作窗口 |
| 舒适／紧凑几何预设 | 适配不同密度与输入场景 | 保留 VS Code 的虚拟列表、行高和定位约束 |
| 扩大组件适配覆盖 | 统一通知、搜索、设置与终端等细节 | 基于现有覆盖补齐具体缺项，逐组件验证键盘导航 |
| 主题组合预览 | 减少反复切换的选择成本 | 当前固定蓝色；更多强调色仍属候选 |
| CSS 结构兼容报告 | 发现类名存在但规则未命中的情况 | 需要真实 DOM 验证，字符串扫描只作初筛 |

## 持续验证

外观 UI-01 至 UI-10 已实现，UI-11 的无障碍与兼容检查贯穿后续工作。
每轮涉及外观的变动复核浅深色、高对比度、键盘焦点、菜单及子菜单、滚动条、
缩放和窄窗。汉堡菜单保持原生位置，不列为待迁移功能。
验证方法与证据边界见 [开发验证](开发验证.md#按改动类型验证)。
