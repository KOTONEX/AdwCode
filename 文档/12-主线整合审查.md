# 4.15.1 主线整合审查

本轮以 4.15.0 的 `3513ebc1` 为基线，对 Rust 工具、TypeScript 扩展及测试、
浏览器脚本、工作流、清单、文档和随附资产进行完整审查。修复后将 Rust 工具链与
TypeScript 脚本实现整合到 `main`，扩展版本改为 4.15.1。本轮只提交并推送主线；
标签、GitHub Release 和扩展市场发布不在本轮范围内。

## 修复

1. 外观安装把显式 `null` 的全局加载引用当作缺省值，且在写入后才发现非法的工作区
   引用。现在只对 `undefined` 使用缺省值，并在写入文件和配置之前校验有效引用。
   回归分别验证两种非法配置都不会改变文件、全局引用或配置写入次数。
2. 操作失败后，如果编辑器的错误提示 API 也拒绝，内部队列会持续拒绝并跳过后续
   操作。现在单次调用仍传播提示错误，内部队列恢复为可继续执行的状态；回归验证
   紧接着排队的操作仍执行。
3. TypeScript 可以通过导入固定源码目录之外的文件生成额外脚本，但这些脚本不在
   打包清单中，运行时可能缺少模块。编译现在校验全部临时产物，仅接受已登记产物。
   真实编译回归验证额外模块被拒绝，且原脚本和待清理的过时脚本均保持不变。
4. 自有字体生成忽略目录条目的读取错误，空来源还可能生成只有 `.notdef` 的字体。
   现在传播读取错误，并拒绝空来源和没有轮廓段的字形。回归覆盖空目录、空路径与
   仅移动起点的路径，失败时保留原字体。
5. 工作台基准把选择器模式参数识别为 `True`，而 Rust 传入 `true`，使
   `--仅选择器` 被忽略。现统一小写值；真实工作台结果确认该模式启用、包含三组
   样式，且仅采样非活动状态切换。

同步修正文档中的旧 JavaScript 源码路径、主线手动工作流说明与历史迁移描述，
明确整套外观组件选择已实施、细粒度 CSS 模块开关仍是候选。本轮没有新增依赖。

## 验证

- `cargo run --quiet -- 检查` 全部通过，包含格式、clippy、Rust 回归、严格 TS
  编译、Node 语法、离线事务回归、清单及主题校验；工作流通过 actionlint。
- 真实扩展宿主验收完成，VS Code 1.140.0 中五个命令与用户/工作区配置作用域通过。
  本机报告为 `builddir/4.15.1宿主验收.json`。
- 独立真实工作台完成浅色、深色的选择器模式验收，每种样式预热一次、采样四次。
  `method.selectorsOnly=true`，三组样式及生命周期验证通过；报告为
  `builddir/4.15.1选择器验收.json`。这些样本用于验证模式，不作为性能提升结论。
- 逐个解析 22 份 JSON、155 份 XML/SVG，解码 69 张 PNG，并验证五份字体的表边界
  和字形数量；检查 PNG 图集。主题、全部自有及导入字体重新生成后无资产差异。
  相对文档文件链接检查通过；第三方许可文件相对已审查的 4.0.0 未变化。
- 提交后按贡献规则，在临时完整历史克隆中检出提交、生成主题和字体、两次打包并
  核对字节、校验源码及编译脚本入包，再安装绝对路径 VSIX 并核对 4.15.1。
  安装完成后清理克隆；推送后核验主线同提交的 GitHub CI。

隔离安装和远端 CI 是主线整合的执行验收步骤；本轮不重载用户当前窗口，也不操作
外观加载器。工作区原有私有编辑器设置与调试日志保持原样，不提交、不进入 VSIX。
