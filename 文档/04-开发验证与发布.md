# 开发、验证与发布

## 开始工作

先阅读 [AGENTS.md](../AGENTS.md)，查看 `git status --short` 与本次任务涉及的
差异。保留与本次任务无关的修改和未跟踪文件，避免未经确认的工作区清理。
任务涉及发布时读取 `package.json`、Git 标签与提交历史，以及发布工作流。

扩展不会因文件改动自动重载；如需重载，由操作者在保存工作后手动执行，
避免中断扩展会话或调试任务。
离线测试使用模拟对象；需要界面验证时使用独立测试窗口，或由操作者手动预览。

## VS Code 工作区配置

源码仓库的 `.vscode/settings.json` 提供开发与外观试用配置，仅在打开本仓库时
生效。Rust 工具链由 `rust-toolchain.toml` 固定为 1.99，并包含 clippy 与
rustfmt；cargo 与编辑器通过 rustup 读取同一工具链，无需配置解释器路径。
TypeScript 严格编译使用 `tsconfig.json`，推荐扩展记录在
`.vscode/extensions.json`。全部 TS 的编译、打包及离线测试需要全局安装的
Node.js 与 TypeScript 编译器（`npm install -g typescript@7.0.2`），项目不引入
`@types` 依赖。

外观预览随系统明暗模式选择 AdwCode：浅色采用彩色状态栏变体，深色采用普通变体，
高对比度的两个首选主题沿用原方案；开启命令中心，并采用 AdwCode 产品图标。
字体沿用用户设置；缩进和第三方资产的保存例外由 `.editorconfig` 与 EditorConfig 扩展管理。

构建命令统一由 `adwcode` 提供：开发期运行 `cargo run --quiet -- <子命令>`，
发布产物为 `./target/release/adwcode <子命令>`。`builddir/` 用于编译后的 `脚本/`、基准结果与
发布说明等产物；工作区不依赖编辑器的构建集成，也不会在打开时自动配置。菜单位置、
标题栏和原生窗口控件等应用级配置在用户设置中维护；工作区配置不会替代 CSS 的
安装与手动加载。

本项目的开发语言是 Rust 与 TypeScript，不提供 C/C++ 编译单元；仓库提交的工作区
配置不包含 C/C++ 编译设置，也不推荐 C/C++ 扩展。

扩展通过 `contributes.configurationDefaults` 声明外观与布局默认值，和工作区
共享同一组主题、产品图标及布局初始值；用户或工作区的显式配置始终优先，
扩展不改写用户设置，也不提供应用或恢复命令。

设置作用域见 [VS Code 说明](https://code.visualstudio.com/docs/configure/settings)，
Rust 工具链文件的读取方式见
[rustup 工具链说明](https://rust-lang.github.io/rustup/overrides.html#the-toolchain-file)。

## 按改动类型验证

| 改动 | 必做验证 | 额外核对 |
| --- | --- | --- |
| 配色、语法映射 | `cargo run --quiet -- 主题`，完整检查 | 源修改与生成 JSON 一起提交；颜色键合法、对比度合理 |
| CSS 外观 | 完整检查，`cargo run --quiet -- 检查样式` | 类名检查只是初筛；视觉、裁切和焦点需单独验证 |
| 窗口状态脚本 | 完整检查，`cargo run --quiet -- 工作台基准` | 对照非活动视觉、正文、高对比度保护、新增导航与观察器释放；不重载工作窗口 |
| 扩展行为 | 完整检查 | API 类型声明、配置默认值、命令清单和错误路径同步 |
| 扩展图标 | PNG、来源记录与设计说明同步，完整检查并打包 | 参考 `资产/README.md`；保留实际源文件，核对清单、README 与 VSIX 图标资源；候选稿不随包分发 |
| 文档与提示 | 完整检查 | 简体中文、路径和命令准确，不引用未提交的文件 |
| 发布与打包 | 构建、完整检查、`cargo run --quiet -- 打包` | 版本一致，产物齐全，不包含私人待办或调试日志；公共候选清单明确区分实现状态 |

首次运行 `cargo build` 会按 `rust-toolchain.toml` 获取固定工具链并编译。全部脚本
的编译、打包和检查需要全局安装的 Node.js 与 TypeScript 编译器（`npm install -g typescript@7.0.2`）。
完整检查为：

```sh
cargo run --quiet -- 检查
```

`adwcode 检查` 聚合 `cargo fmt --check`、`cargo clippy --all-targets`、
`cargo test`、`adwcode 校验`、`adwcode 验证设置`、严格 TS 编译、产物 Node.js 语法检查与离线测试；
缺少 Node.js 或 tsc 时直接失败，不把跳过记为通过。`adwcode 类型检查` 只运行
`cargo check --all-targets` 与 `tsc --noEmit`，适合快速迭代。

Rust 代码由 `cargo fmt` 统一格式化（`cargo run --quiet -- 格式化`），
`cargo clippy` 警告视为错误；两者覆盖全部自有 Rust 源码，包括图标生成器与
性能基准。TypeScript、编译后 JS 与 CSS 分别由 tsc、Node.js 和 `cargo run --quiet -- 检查样式`
验证。

`cargo run --quiet -- 校验` 校验主题及产品图标的注册和文件完整性、十六进制
颜色、键覆盖与对比度，缺少产物时失败；它不负责证明产物与生成器逐字节一致。生成后核对 Git 差异；
CI 的生成校验要求重新构建后 `主题/` 和 `package.json` 不产生额外差异。
发布工作流构建固定蓝色的 6 个主题变体，核对产物与提交一致，通过完整检查后打包。

`cargo run --quiet -- 验证设置` 单独验证清单默认设置、五个 Linux 命令和工作区能力。
发布权限使用 `cargo run --quiet -- 发布策略 --引用 refs/tags/v<版本>` 判断；
CI 追加 `--输出 "$GITHUB_OUTPUT"`，将版本、候选和市场发布权限传给后续步骤。
非主线提交或预发布版本只创建候选 Release；缺少主线或完整历史、Git 出错时失败。
发布策略和清单验证的回归已迁入 Cargo，完整检查仍需 Node.js 执行真实扩展脚本。

缺少随附颜色键表时，主题校验直接失败。CSS 校验找不到已安装的样式表时也会
失败，可用 `cargo run --quiet -- 检查样式 --样式表 /路径/workbench.desktop.main.css`
指定构建。完整离线检查在未安装 VS Code 时跳过类名对照；跳过不代表界面已验证。
刷新默认数据时，所有下载与解析成功后才写入四个数据文件，下载失败保留原数据。

## 性能测量

按任务需要运行 `cargo run --quiet -- 性能基准`，在临时副本中测量生成、
校验与打包，并运行模拟宿主下的扩展逻辑基准。结果保存为
`builddir/performance.json`，不覆盖仓库的主题或 VSIX。

真实工作台的 CSS 对比使用 `cargo run --quiet -- 工作台基准`，需要独立安装的
Playwright；它创建专用窗口与临时配置，结束后关闭，不重载工作窗口。
运行方式见源码仓库的 `基准/README.md`，本机方法、结果与原始样本见
[性能测试](07-性能测试.md)。性能测试不在常规检查中自动运行，也不设跨机器耗时门槛。

## 手动预览

1. 配色源码有变化时先 `cargo run --quiet -- 主题`。
2. 如果用 VSIX 安装扩展，先打包并直接安装即可更新，无需卸载旧版或额外升级步骤；
   详见 [中文接口迁移](08-中文接口迁移.md)。符号链接开发安装直接读取仓库。
3. 执行“AdwCode: 安装 GNOME 外观（CSS）”，更新副本与加载配置。
4. 保存工作后执行加载器的“Reload Custom CSS and JS”并重载窗口。
5. 检查浅色、深色、高对比度、键盘焦点、菜单及子菜单、横纵滚动条、缩放与窄窗。

首次尚未启用加载器时，应使用其“Enable Custom CSS and JS”。VS Code 升级后
需要重新应用补丁。命令沿用加载器实际显示名称，不把外部命令自行改名。

记录验证边界：静态检查、单个界面的人工确认和完整截图回归，三者
含义不同。避免用旧截图或单个界面作为全部外观已验证的依据。

## 提交与发布

VSIX 产物不变的改动只提交与推送，不更新发布版本号、不打版本标签、不创建 Release。
是否发布以实际打包内容的变化为依据，不因产生新提交而自动发布。

1. 明确本次提交范围，按路径暂存，排除调试日志、构建产物及无关改动。检查暂存差异及 `git diff --cached --check`。
2. 使用 [贡献规范](../CONTRIBUTING.md) 的中文类型前缀，描述最终实际行为。
   正文可列修改原因与验证结果，避免只有“准备发布”等过程性描述。
3. 本机 Git 身份缺失时核对 gh 账号和已有作者信息；必要时询问，不伪造邮箱。
   临时身份可通过 `git -c user.name=… -c user.email=… commit` 指定。
4. 版本只修改 `package.json`；提交后通过 `cargo run --quiet -- 变更日志` 从 Git
   历史生成日志，不手工维护版本章节。更新版本不等于
   已公开发布，提交也不等于已推送。
5. 打包检查 VSIX 的版本、主题清单和归档完整性；`[Content_Types].xml` 中的
   扩展名不带前导点，CSS 类型为 `text/css`。VSIX 不提交到仓库。
6. 确认发布范围与权限后推送对应 `v<版本>` 标签，触发发布工作流。标签提交尚未进入
   `main` 或版本号带预发布部分时，Release 标为候选，不更新 latest，也不发布市场。
   CI 同时检查 `main` 与 `rust`；重新生成主题和全部字体必须与受跟踪产物一致。
   正式市场发布要求标签版本一致、提交已进入 `main` 且版本不带预发布部分；还需要
   `VSCE_PAT`、`OVSX_PAT`，缺失时工作流跳过对应市场，不宣称市场已经发布。
   同一引用的发布任务串行执行；重跑时保留已有 Release 和同名 VSIX，只补齐缺失附件
   并更新说明，市场发布复用已公开的 VSIX。不要移动已发布的版本标签；确需修正
   附件时，应单独确认替换范围。

文档记录稳定流程；提交状态、环境配置和发布结果以实际检查为准。
公共文档中的相对链接必须指向随仓库提交的文件。

## 本地与 CI 共用上传

完成完整检查、提交和版本标签校验后，打包与上传使用相同入口：

```sh
git fetch origin main --tags
cargo build --release
./target/release/adwcode 打包
./target/release/adwcode 发布上传 --引用 refs/tags/v<版本> --目标 Release --预演
./target/release/adwcode 发布上传 --引用 refs/tags/v<版本> --目标 Release
```

`--预演` 不访问发布服务，只校验完整历史、标签与 HEAD/清单一致、打包源文件
无未提交修改及 VSIX 内容。先重新打包，避免把未打标签时的变更日志上传。
上传使用清单中的 GitHub 仓库，需已认证的 `gh`（CI 使用 `GH_TOKEN`）。
上传命令假定完整检查已成功，不代替完整检查；本地发布仍须获得操作者授权。

已有 Release 只补齐缺少的附件并更新说明；已有同名附件下载到临时目录，
与当前标签打包内容一致才复用，内容不同直接失败，保留公开附件。
只有 HTTP 404 允许创建 Release，其他网络/认证错误直接失败。
非主线或预发布版本固定为候选 Release，不设为最新，也不允许市场上传。

正式版本在主线可达时，可复用相同 VSIX：

```sh
./target/release/adwcode 发布上传 --引用 refs/tags/v<版本> --目标 市场
```

需 `npx` 与 `VSCE_PAT` / `OVSX_PAT` 环境变量；缺少任一令牌时仅跳过对应市场。
外部工具原生读取令牌，不将令牌写入参数、文件或日志。VS Code 市场沿用
`--skip-duplicate`；Open VSX 仅在明确不存在时上传，查询失败直接中止。
同版本中途失败后可以重试，命令不会回滚已成功的远端上传。
令牌环境变量是外部工具支持的接口，见
[vsce](https://github.com/microsoft/vscode-vsce) 与
[Open VSX CLI](https://github.com/eclipse-openvsx/openvsx/blob/main/cli/README.md)。

## 自动变更日志

仓库不维护手写的 `CHANGELOG.md`。完整 Git 历史、提交标题与版本标签是唯一输入；
已发布记录见 [GitHub 发布页](https://github.com/KOTONEX/AdwCode/releases)。

```sh
cargo run --quiet -- 变更日志
cargo run --quiet -- 发布说明
```

第一条生成 `builddir/CHANGELOG.md`，第二条生成 `builddir/release-notes.md`。
两者均是忽略的构建产物，不入库；可通过 `--输出` 指定输出位置。
提交标题按 `新增`、`修复`、`文档`、`测试`、`重构`、`杂务`、`初始化` 分组，
未分类的旧标题归入“其他”。日志不包含提交正文和未提交修改；正式记录需要先提交。

主线可达的 `v<版本>` 标签作为发布边界，按主线提交顺序排列；版本日期使用标签
所指提交的日期。每个范围包含合入主线的非合并提交，合并提交自身不重复列出。
不在当前主线上的标签不参与划分，首个版本包含此前全部提交，最近标签之后的
提交归入“未发布”。同一提交有多个版本标签时失败，避免发布范围产生歧义。

发布工作流执行 `./target/release/adwcode 发布说明 --标签 "$GITHUB_REF_NAME"`，必须同时
满足标签存在、指向 HEAD 且与 `package.json` 版本一致。无标签的本地说明明确标为
预览，不能作为发布校验通过的证据。浅克隆会失败；克隆时获取完整历史和标签，
CI 与发布使用 `fetch-depth: 0`，不在检查时自动访问网络补齐历史。

普通打包自动从 Git 生成 `扩展/CHANGELOG.md` 并写入 VSIX，无需先运行日志
目标。无 Git 的源码导出副本须显式传入先前生成的日志：

```sh
./target/release/adwcode 打包 --变更日志 /路径/CHANGELOG.md
```

性能基准在计时前生成固定日志，临时源码副本的打包使用该日志，不复制 Git 仓库，
也不把生成历史日志的耗时计入 VSIX 打包测量。

## 更新项目说明

功能行为变化时同步相关文档：架构说明记录已实现行为，待办记录剩余范围，
提交标题记录具体变化，由自动日志汇总；AGENTS.md 只保留稳定约束和入口。不要复制多份完整
实现说明，也不要把“计划做”写成“已经完成”。

独立真实宿主测试：`cargo run --quiet -- 宿主测试`，可用 `--编辑器程序 /路径/code`
和 `--输出 /路径/报告.json`。需要可用桌面显示；CI 使用 Xvfb，缺少显示时不自动跳过。
通过 `--extensionTestsPath` 在独立宿主运行，见 [VS Code 测试说明](https://code.visualstudio.com/api/working-with-extensions/testing-extension)。

CI 的临时下载版 VS Code 使用 `宿主测试 --禁用沙箱`，避免未安装的 Electron 沙箱辅助程序权限导致启动失败；
此参数只传给本次独立测试进程，本地默认仍使用沙箱，不修改系统权限或当前窗口。

### 发布命令超时与诊断

GitHub 查询限时 60 秒，Release/附件操作 180 秒，市场命令 600 秒。超时会清理本次
独立进程组并返回失败；错误包含阶段与退出码，GH_TOKEN、GITHUB_TOKEN、VSCE_PAT、OVSX_PAT
在 stderr 诊断中遮蔽。工具输出保存在临时文件并有读取上限，完成后清理。
网络失败后可重新执行同一发布命令，已有附件继续逐字节核验；远端已经成功的步骤保留。

### 编辑工作台颜色规则

编辑 `源码/库/界面映射/规则.json`，保持格式版本2以及现有许可声明。规则数组依次执行，
`放` 登记、`放可选` 允许省略、`覆盖` 原位更新或在末尾追加，`终端` 插入固定16色。
`注释` 只保留说明；规则可加 `条件`（深色、高对比度、浅色标签、彩色状态栏）。

每个颜色行只能指定 `角色`、十六进制 `常量` 或 `计算` 之一。`计算` 必须是
`源码/库/界面映射/计算.rs` 中的固定名称；透明合成、叠加、色阶、样式回退和条件计算
由 Rust 编译检查，不再解析递归表达式。可选颜色的省略由对应计算返回空值实现。
未知字段、名称、条件、错误类型以及显式 null 均失败；类型化读取使用 serde。
修改后运行 `cargo run --quiet -- 检查`、重新生成主题并审查差异，再打包；规则随编译更新。

### 宿主 CI 触发与缓存

相关模块变化、每周首次 CI、官方稳定版本更新以及手动触发都会运行独立宿主。
纯版本号、颜色、字体、摘要及文档变化在本周最新版已验收时跳过宿主；完整检查和
资产校验始终执行。编辑器使用精确版本缓存，周记录只在真实测试成功后写入。
无提交时用 `gh workflow run ci.yml --ref main` 手动验证主线与最新版编辑器；
验证其他开发分支时替换 `--ref`。

CI 已编译工具后的辅助步骤统一为 `adwcode 持续集成 <步骤>`：
`宿主改动`、`宿主版本`、`宿主计划`、`宿主成功`、`登记工具`。这些命令读取
GitHub Actions 的事件、输出文件与临时目录环境；宿主计划另外读取步骤环境 `相关`、`已验收`。
宿主基线未知时保守运行，手动触发强制运行。清单只改版本或字段排序不触发宿主；
其他清单改动仍触发。登记工具读取当前运行的 release 二进制，记录提交、平台和 SHA-256。
Release 查找产物和校验工具时尚不能运行该工具，因此启动阶段保留 Python，
不额外编译来执行校验。
