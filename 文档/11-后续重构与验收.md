# 后续重构与验收

本文记录 4.3.0 至 4.15.0 在 rust 分支的重构与候选发布，各方向独立提交和验收。
这些阶段的 main 未变；4.15.1 完整审查后将现有实现整合至 main，不创建发布标签。

| 版本 | 方向 | 验收 |
| --- | --- | --- |
| 4.3.0 | 扩展模块化 | 原有状态、引用和文件/配置回滚测试；完整检查；隔离安装 |
| 4.4.0 | 测试接口与独立宿主 | 共用显式模块接口；独立 Extension Development Host 中命令和配置作用域 |
| 4.5.0 | SVG/字体管线拆分 | 保持算法、容差与顺序；全部生成字体和预览逐字节一致 |
| 4.6.0 | 基准公共工具 | 复制过滤差异、符号链接拒绝和进程组清理回归 |
| 4.7.0 | 发布执行器 | 超时、退出码、阶段与脱敏回归；附件复用及不一致拒绝 |
| 4.8.0 | 颜色映射规则与表达式 | 原有金样例；全启用强调色的8个组合输出一致；非法规则拒绝 |

## 4.3.0 扩展模块化

入口只装配本机依赖并注册五个命令。组件、字体、引用、状态、事务使用独立工厂；
每次创建服务均拥有自己的字体缓存、输出通道和串行队列。文件和配置的恢复仍由
事务模块整体协调。无构建步骤、无运行时依赖的 JS 发布方式保持。

语法检查递归覆盖扩展模块，TypeScript 检查覆盖 `扩展/**/*.js`。离线测试使用
显式服务接口，不再访问 VM 内的私有变量；宿主夹具的共用整理在下一阶段进行。
基准的创建场景改名为“外观服务创建（模块实例）”，测量模块工厂，不能与旧 VM
加载场景直接比较；其余场景仍调用真实状态逻辑和命令注册实现，报告结构保持。

## 4.4.0 测试接口与独立宿主

`测试/扩展宿主.cjs` 提供服务工厂和真实 CommonJS 入口加载器，离线回归与基准共用。
VM 只隔离入口依赖，测试不再访问私有作用域。补齐真实入口五命令注册/释放、取消无写入
和实例状态隔离。基准加载场景包含入口加载，名称改为“扩展加载（显式宿主接口）”。

`cargo run --quiet -- 宿主测试` 启动独立用户数据、扩展目录及临时工作区；测试真实 API
的命令注册、Global/Workspace 优先级和状态命令，恢复设置后关闭进程组并清理。
不运行安装、加载器或重载命令；报告为 `builddir/宿主测试.json`。独立宿主不代表外观视觉验收。
CI 通过官方测试工具下载稳定编辑器并在 Xvfb 下执行，此工具不成为扩展运行依赖。

4.4.0 发布前 CI 发现下载版 Electron 的沙箱辅助程序没有 root/setuid 安装权限；
独立测试新增明确的 `--禁用沙箱` 参数用于 CI，本地默认行为保持沙箱启用。

## 4.5.0 SVG/字体管线拆分

`源码/库/图标生成/mod.rs` 保留来源校验与两个生成入口；`几何.rs` 负责路径、布尔运算和字重，
`矢量解析.rs` 负责 XML/SVG 与绘制策略，`字体封装.rs` 写入字体表，`预览.rs` 导出 SVG，
`测试.rs` 保留全部图标回归。跨模块接口只对本管线可见；算法、常量、容差和遍历顺序保持。
以 4.4.0 资产为基线，重新生成全部字体及 SVG 预览后逐字节核对，完整检查与隔离安装另行通过。

## 4.6.0 基准公共工具

`运行工具.rs` 提供程序查找、受管进程组和显式过滤策略的目录复制；性能基准、工作台基准
与独立宿主测试共用，避免宿主测试依赖工作台基准实现。性能基准仍过滤 Python 缓存，
工作台复制保留全部内容；来源与目标拒绝符号链接，被过滤条目也先校验，IO 错误传播。
进程清理保持 TERM、最多一秒等待、KILL 后回收，主进程退出仍清理后代。
新增过滤差异、缺失来源/文件目标、来源/目标/被过滤符号链接回归，保留真实错误返回清理测试。

## 4.7.0 发布执行器

外部发布工具统一进入 `发布执行.rs`，独立进程组、无交互输入，stdout/stderr 写入临时文件
避免管道阻塞。GitHub 查询 60 秒、附件和 Release 操作 180 秒、市场发布 600 秒超时；
正常退出、错误或超时都清理本次进程组。stdout 超过 8 MiB 停止发布；诊断读取有上限。
错误携带具体阶段、退出码或超时，去除终端控制序列并遮蔽四种发布令牌，诊断截短后输出。
仅明确 HTTP 404 允许创建 Release，401/403/429/服务端错误仍停止；附件一致性与市场权限不变。
真实子进程测试覆盖退出码、脱敏、较大 stderr 不阻塞及忽略 TERM 后代的超时清理。
已成功的远端操作无法回滚，重新运行仍使用相同附件核验；没有替换公开附件的操作。

## 4.8.0 颜色映射规则与表达式

按全部方向授权将原先建议暂缓的颜色映射作为最后一项实施。`界面映射/规则.json` 保存
983 条登记/覆盖、注释及终端插入点；Rust 只保留有序收集与受限表达式解释器。
规则编译时嵌入并在进程内只解析一次，不引入外部代码执行、额外运行依赖或 Cargo 依赖。
普通主题的空值省略、原位覆盖、终端16色位置与样式缺失回退语义保持。

规则校验字段、类型、操作、条件、比例范围、色阶级数和嵌套深度；不存在的角色/表面返回错误。
未知操作或字段不会忽略。原有8个金样例通过；另以4.7.0当前实现为独立基线，按实际启用
强调色清单比较明暗、对比度及彩色状态栏组合，8个场景颜色与顺序逐字节相同。
验收记录在 `builddir/4.8.0映射验收.json`；完整检查、主题再生成与隔离打包另行验收。
本方向改善规则维护方式，不承诺性能提升，解释器与格式校验仍需要维护。

## 后续四项精简

工作流先取消工具链动作的隐式缓存，保留一次显式缓存；成功的 push CI 保存同提交
release 工具及 SHA256 元数据，标签发布校验后复用。无可用产物时执行完整构建，
API 或校验失败停止。标签上重新打包，保留变更日志语义。

### 4.9.0 平坦颜色映射

格式2映射行只引用角色、常量或72项固定计算；取消递归解释器及其运算格式。
类型化读取严格区分缺省字段与 null，拒未知字段、计算和条件。复杂计算由 Rust
编译检查，样式回退保持惰性。JSON 从120819字节减少至88911字节；Rust源码较旧
解释器增加，换取计算可直接阅读与编译检查，不以源码行数或速度作为收益。
八种组合的完整颜色与顺序逐字节一致，金样例、覆盖、可选省略和终端插入回归通过。

### 4.10.0 基准默认只测墙钟

默认阻塞等待子进程，不执行高频资源轮询；`--详细资源` 保留原 CPU/VmHWM 测量。
报告 schema2 保留字段，未测或未采到的资源为 null。继续保留指纹、临时副本、
进程组清理和子命令失败处理；两模式回归及本机真实五次基准另行验收。

### 4.11.0 宿主 CI 按改动与周运行

真实宿主在相关扩展、测试、声明、启动器和工作流变化时运行；清单仅版本变化不触发。
每次 CI 解析官方最新稳定版，编辑器按平台与精确版本缓存。每周首个 CI 或稳定版
更新时强制验收；只有成功测试后的记录才进入周缓存。无法确定比较基线时完整运行。
保留 main 不动，因此采用每周首个 CI 的检查，而非只能从默认分支触发的 cron；
无提交时可用 `gh workflow run ci.yml --ref rust` 手动运行，强制测试最新稳定版。

### 4.12.0 SHA-256 复用成熟实现

手写算法替换为 `sha2`，函数签名和摘要内容保持。以标准向量、二进制填充边界、
全部图标来源摘要与基准指纹验证兼容；完整主题和字体生成仍要求无资产差异。
取舍是增加构建期 Cargo 依赖，以减少项目内的算法维护；不增加扩展运行时依赖。

### 4.13.0 无桥接的 CI 辅助逻辑

移除 `测试/宿主触发.cjs`，路径和清单判断及回归纳入 Cargo；CI 的稳定版本、UTC ISO 周、
宿主计划、成功记录和发布工具登记均调用 `持续集成` 命令。日期采用 time 库，HTTP 复用
ureq，摘要复用 sha2，登记使用已有批次写入。保留 SDK 下载封装、真实 JS 测试及 Release
启动校验 Python。回归覆盖真实 Git 的 push/PR/手动与缺失基线、清单变动、跨年周号、
缓存计划、版本响应和产物摘要；生成主题、字体及扩展行为保持不变。

### 4.14.0 通用实现复用第三方库

有序字符串映射使用 IndexMap，重复键原位更新；通过 Slice 比较保留顺序敏感的相等语义。
颜色规则的 None 占位、重复登记及后续覆盖属于规则行为，继续保留操作记录与回归。
手写 JSONC 扫描替换为 jsonc-parser，十项选项显式配置，仅注释和尾逗号为真；
另校验根对象，空输入、纯注释、null、其他 JSON5 语法、非有限数及未闭合注释均拒绝。
URL、转义字符串、重复键和多行诊断纳入回归，全部解析成功后仍统一事务写入键表。

版本标签、打包清单、发布权限及宿主稳定版本使用 semver；稳定宿主要求无预发布或
构建标识。版本验证收紧至标准 SemVer，拒绝数字前导零、空标识及非 ASCII，
主次修订数值受库的 u64 范围限制。XML 转义复用现有 quick-xml 0.41 的五字符转义。
发布链接的手写百分号编码替换为 percent-encoding，安全字符及 UTF-8 编码保持，
中文、保留符号、控制字符与安全字符纳入回归；该库已在 HTTP 传递依赖中。
新增依赖只用于构建工具；完整检查、八场景金样例、主题字体再生成、确定性打包及
隔离安装共同验收，不承诺扩展运行时性能变化。

## 4.15.0 全部脚本迁移 TypeScript

8 个扩展模块、窗口状态脚本、4 个测试脚本及2个基准脚本全部改为 `.ts`；
原有章节中的 JS/CJS 路径记录当时的实现，当前源路径统一使用 `.ts`。
启用严格检查、`noEmitOnError` 和 Node16 模块解析，使用手写的最小 Node、VS Code
及浏览器工具声明，不增加 `@types` 或扩展运行时依赖。

4.15.0 当时的 `编译脚本` 固定 TypeScript 7.0.2；后续已按 [工具链政策](../AGENTS.md#工具链政策)
取消固定，改用最新稳定版并拒绝预发布编译器。在临时目录编译，成功后批次替换
`builddir/脚本/` 中的15个 JS 产物并清理过时脚本；类型错误保留旧文件但使命令失败，
检查、打包、宿主和基准不会继续使用旧产物。产物目录及源码拒绝符号链接。
打包先校验 TS 源码均在归档范围内，再重新编译，保留完整源码、许可证和运行产物，
未跟踪的脚本不能借编译进入 VSIX。

扩展入口改为 `builddir/脚本/扩展/扩展.js`，CommonJS 供 VS Code 宿主使用；
窗口状态保持无模块依赖的浏览器 IIFE，安装副本仍名为 `窗口状态.js`，
兼容旧源路径引用并识别新的编译产物路径。CI、快速复用工具的发布路径、
独立宿主、离线回归和性能基准均调用编译后的脚本。打包墙钟现在包含 TS 编译，
不与迁移前仅归档的耗时直接比较。

浏览器工具的页面回调在浏览器内执行，使用 `window.performance`；Node 侧计时使用显式导入的 `节点计时`，避免 TypeScript 的 CommonJS 导入改写进入浏览器回调。独立工作台验证覆盖浅色/深色、窗口活动状态切换、真实滚动与 1000 行侧栏压力场景。

## 4.15.2：最新稳定工具链

Rust 改用 `stable` 渠道，Node.js 与 TypeScript 在 CI 中使用最新稳定发行版，
不再固定数字版本。开发前更新并记录实际版本；常规编译不联网升级全局环境。
脚本构建接受稳定版编译器并拒绝预发布版本，继续保留严格编译与事务写入。
工具链政策写入项目规范；依赖锁文件、Rust Edition 和 TS 运行目标继续保留。
